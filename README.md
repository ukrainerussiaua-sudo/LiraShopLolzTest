# 🥭 MANGO SHOP BOT

Telegram-бот магазина: **аккаунты** (покупка на Lolz Market), **Stars / Premium** (Fragment), **Голда** (заявки), **TON** (покупка и пополнение).
Всё в **гривнах (₴)**, интерфейс на русском. Премиум-эмодзи по гайду https://emoji.wivvi.net.

- Поддержка: @mango_user · Канал: https://t.me/mangostarss (**обязательная подписка**) · Чат: https://t.me/mango_markett
- ⚠️ Бот должен быть **администратором канала @mangostarss**, иначе проверка подписки не работает.

## Запуск
```bash
pip install -U -r requirements.txt      # aiogram обновите: нужен Bot API 9.4+ (иконки на кнопках)
cp .env.example .env                    # заполнить
python main.py
```
Supabase: SQL Editor → вставить **`supabase_schema.sql`** целиком → Run (скрипт безопасно запускать повторно: добавит новые таблицы 13–16).
В `.env` нужен ключ **service_role**.

## Разделы бота
| Раздел | Как работает |
|---|---|
| `/start` | Подробное приветствие: Stars, Premium, TG-аккаунты, Голда, TON + ссылки на канал/чат/поддержку |
| ✈️ Telegram аккаунты | Покупка на Lolz Market. Цена страны — в ₴, задаётся в админке. Сравнивается с ценой Lolz (₽) по курсу из «Себестоимость → Курс Lolz» |
| ⭐ Stars / 💎 Premium | Оплата с баланса, доставка через Fragment (как раньше) |
| 🥇 Голда | Купить / Продать → сумма → комментарий (или «Пропустить») → проверка → «Отправить заявку» → **«Заявка №N»** уходит всем админам |
| 💠 Купить TON | Цена = курс + наценка продажи. Клиент выбирает количество, вводит свой адрес, платит с баланса — бот отправляет TON со своего кошелька |
| 💠 Продать TON | Клиент шлёт TON на адрес приёма с ID в комментарии и получает ₴ на баланс по курсу выкупа (курс − наценка покупки) |
| Пополнить | 💳 Перевод на карту · 🪙 Crypto Bot (счёт в UAH) · 💠 TON |

### Голда — заявки
Админам приходит карточка: тип, сумма, комментарий, клиент. Кнопки: **Написать клиенту** (по @username), **Ответить в боте** (ответ приходит клиенту
с кнопкой «Ответить» — получается переписка по заявке), **Взять в работу / Выполнено / Отклонить** (клиент получает уведомление о статусе).
Открытые заявки: админка → «Заявки Голды». Курс (необязательно, для ориентира в заявке): «Курс Голды».

### Пополнение картой
Клиент видит реквизиты → переводит → «Я оплатил» → шлёт скрин/PDF. Админам приходит **чек с кнопками** «Подтвердить / Отклонить / Другая сумма».
Один и тот же файл чека второй раз не принимается (защита от повторов). Автопроверки банка нет — подтверждает админ.
Реквизиты: админка → «Реквизиты карты» (или `CARD_*` в `.env`).

### Пополнение через TON
Клиент отправляет **любую сумму TON** на адрес приёма и пишет в комментарии **свой ID** (бот показывает его). Бот сам каждые ~30 сек ищет переводы
и зачисляет `TON × курс`; кнопка «Проверить баланс» делает проверку сразу, «Отменить» закрывает экран.
- Адрес приёма и курс: админка → «Настройки TON». Если адрес не задан, а `TON_MNEMONIC` есть — принимает на кошелёк бота.
- «Продать TON» в каталоге работает тем же механизмом, что и пополнение (тот же адрес, ID в комментарии, те же защиты) — деньги идут на баланс бота в ₴.

### Курс TON и наценки
Админка → «Настройки TON»:
- **Источник курса** — кнопка-переключатель: **Сайт** (CoinGecko, TON→UAH, обновляется раз в минуту) или **Свой** (число из «Свой курс»).
- **Покупка у клиента (−)**: сколько ₴ вычитается из курса. Это курс и для «Продать TON», и для пополнения баланса TON-переводом.
- **Продажа клиенту (+)**: сколько ₴ добавляется к курсу при «Купить TON».
- Пример: курс 130, покупка 4, продажа 5 → клиент получает 126 ₴ за 1 TON и платит 135 ₴ за 1 TON. Заголовок раздела показывает текущие базу, выкуп, продажу и спред.
- Если курс сайта не обновлялся дольше 15 минут (сбой источника), TON-операции ставятся на паузу, а админам приходит предупреждение — можно переключить на «Свой».
- **Защита:** каждая транзакция записывается в БД по хэшу (`ton_deposits`, PK = tx_hash) **до** зачисления — повторно не зачтётся; старая история адреса
  (до момента настройки) игнорируется; перевод без ID / с несуществующим ID не зачисляется — админам уходит уведомление и запись в «TON без привязки».
- Курс фиксируется в момент зачисления.

## Админ-панель
Статистика (сегодня / 7 дн. / 30 дн. / всё время: **грязная выручка**, себестоимость, реферальные выплаты, **чистая прибыль**, по товарам, пополнения по способам,
сумма на балансах клиентов) · Последние покупки всех · Последние пополнения · Заявки Голды · TON без привязки · Начислить баланс · Пользователь (бан, покупки, код, сброс сессии) ·
Промокоды · Цены аккаунтов · Цены Stars/Premium · Fragment/TON · **Настройки TON** · **Реквизиты карты** · **Курс Голды** · **Себестоимость** · Рассылка.

**Уведомления админам:** каждое пополнение баланса (кто, сколько, чем), каждая продажа (аккаунт/Stars/Premium/TON с прибылью), заявки Голды, чеки на проверку, сбои и неясные заказы.

### Как считается прибыль
`чистая = цена клиента − себестоимость − реферальный бонус`. Себестоимость аккаунта — реальная цена Lolz × курс ₽→₴; Stars / Premium / TON — значения из
админки «Себестоимость» (не заданы → 0). Журнал — таблица `sales`.

## Премиум-эмодзи
Модуль `emoji.py`. В сообщениях обычные эмодзи автоматически заменяются на `<tg-emoji>` (исходящий middleware, `<code>` не трогается);
на кнопках иконка идёт в `icon_custom_emoji_id`, текст кнопок — без эмодзи (соответствие — `_ICON` в `keyboards.py`).
Нужен **Telegram Premium у владельца бота** и Bot API 9.4+. Все ID — из списка https://emoji.wivvi.net.

## Деньги и защита
- Баланс списывается до выдачи; явный отказ → автовозврат; неясный итог (мог уйти аккаунт/TON) → возврата нет, админу 🚨-алерт.
- Все зачисления идут через одну функцию (`billing.credit_topup`) с «claim»-защитой от двойного зачисления.
- Покупка TON: только на валидный TON-адрес; суммы в пределах лимитов из админки.
